## 2. catch-weight 实战解读（核心）

单据上**三种计价单位并存**，把双单位/称重模型演活了：

| 计价方式 | 单位 | 例（下单 → 计价） |
|---|---|---|
| **按重量（catch-weight）** | LB | 牛腩 ~50#/箱 → 实称 **54.53 LB × $5.19 = $283.01**；整鸡 84.70 LB × 1.39 = 117.73；无骨猪臀 76.30 × 2.09 = 159.47 |
| **逐件称重** | CW | 猪蹄 2 CW，单据写明 **"Total Weight: 30.00 ; 30.00 ; 60"**（每箱 30 磅、两箱共 60）× 1.39 = 83.40 |
| **固定价** | CS / BAG / CAN | 芝麻油 4GAL = 44.95/箱；盐 50#/BAG = 7.95/袋 |

**要点**：
1. **客户按箱/袋下单，不按重量买**；肉类取货后称重、按实重定价——正是本系统 catch-weight 模型，已建成。
2. 商品描述常带标称箱重（~50#、41~80#/CS、22#/CS），是"预估/均重"，计价按实称。
3. **逐件称重明细**（30;30）揭示：他们捕获每件/每箱的单独重量，不只一个总重。本系统现每个发运行只存一个 `shipped_weight_lb` 总重——如需完全对齐，要细化为逐件称重（演示是否做到此粒度可议）。

> 金额用**种子现价**，与真实单据价格不同不影响演示——演示的是"下单按箱、称重按磅、系统自动算价"的机制。称重值照真实单据模拟（54.53 等），使 catch-weight 的自动定价看起来真实。

**演示脚本要点**（配合计划书 §7）：
1. CRAVE & COOK 下单 2 箱牛腩 + 若干干货 → 确认订单
2. 生成取货单（告知库位）→ 取货员取 2 箱牛腩 → **称重 54.53 磅 → 系统自动 $338.09** ← 情绪高点
3. 生成出货单/发货 → 签收
4. 干货按箱固定价，与称重肉类对比，讲清"客户按箱买、系统按磅算"
